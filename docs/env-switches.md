# Remaining environment variables

Diagnostic code from the bring-up phase has been removed (`EDEN_NATIVE_*` captures,
traces, profilers, A/B experiments). Only these remain:

| Variable | Effect |
| --- | --- |
| `EDEN_NO_HEAP_REUSE=1` | Turns off reuse of texture banks and descriptors (to isolate a wrong texture). |
| `EDEN_TEXTURE_TABLE_STATS=1` | Logs texture table and bank statistics every 4 s. |
| `EDEN_BACK_THREAD_STATS=1/2` | Logs every 4 s where the thread that prepares draws spends its time (parts of `PrepareDraw`, descriptors, scheduler waits, the Vulkan worker, cache locks, the front of the split). `2` serializes the timestamps (`lfence`), to check a decisive number. Costs about 1-2%: measure draws/s with it off. |
| `EDEN_INLINE_DEFER=1/2` | Experiment (off by default; based on PokeDinner's `EDEN_NX2_INLINE_DEFER`). An inline upload that does not need to go straight to the buffer (a region with no GPU-written data) defers to the next `FlushCaching` the invalidation of the buffer and shader caches (`1`, safe), or also of the texture cache (`2`, as in PokeDinner: a CPU read that downloads a GPU-written image before the next `FlushCaching` would undo the write). |
| `EDEN_FLUSH_DRAWS=N` | How often work is submitted to the real GPU, in draws (32 to 1048576, a multiple of 32). **Default: 128 for Switch 2 titles** (desktop; from PokeDinner 226162edf), about 4128 for others. Shortens the per-frame `Finish` in Fire Emblem (760 to 255 µs). `4096` restores the old period. |
| `EDEN_HELD_WRITE_MERGE=0` | Turns off merging of the game's held writes before they are applied to the caches. On by default: contiguous or overlapping regions in the same 4 KB page become one (in a busy scene, about 400 regions per batch become about 38). |
| `EDEN_GPU_SPLIT=0/1/2` | Emulated GPU on one thread (0), methods on the back thread (1), or also macros on the front thread (2, default). |
| `EDEN_MME_JIT=0` | Runs native macros in the interpreter instead of compiled code. |
| `EDEN_NATIVE_FRONTEND=lower/ampere/auto/compare` | Native shader front end. Default `auto`: the native front end first, with translation to Maxwell for programs it rejects. `lower` translates everything to Maxwell. `EDEN_NATIVE_CENSUS=1` lists every unsupported instruction of each rejected program, not only the first, in the census logged when the game closes. |
| `EDEN_N2DEN_GLOBAL_NOINLINE=1` | Emits shader global-memory access functions as `DontInline` calls (off by default). Programs with many candidate buffers compile much faster on NVIDIA, but in this form the first of two consecutive reads returns 0 on NVIDIA: in OoT, a wall of trees crosses Hyrule Field. |
| `EDEN_N2DEN_SMART_BC1=0`, `EDEN_N2DEN_SMART_BC45=0` | With Smart BC (`astc_recompression`, default), `SMART_BC1=0` keeps opaque textures in BC3 and `SMART_BC45=0` sends luminance to BC1 and luminance+alpha to BC3. Use them to bisect a Smart BC visual defect; BC3 for everything is the BC3 menu option. |
| `EDEN_N2DEN_ASTC_RECOMPRESSION=uncompressed/bc1/bc3/auto/smart` | Overrides the "ASTC Recompression Method" option for one run (for A/B tests or scripts), whatever the config says. |
| `EDEN_N2DEN_RANGE_CACHE=0` | Turns off the per-thread cache of `MaxContinuousRange` answers (walks the page table on every storage buffer bind, as before; for comparisons). |
| `EDEN_N2DEN_BC_REFINE=1` | With Smart BC, refines the colour endpoints of BC1/BC3 blocks (principal axis, least squares): about +2 dB for 1.8x the cost of the BC3 encode. Off by default. |
| `EDEN_NX2_FRAMES_AHEAD=1/0/-1` | How far the game may run ahead of the emulated GPU at vi2 presentation. Without the variable: `1` in Fire Emblem: Fortune's Weave, `0` in other games. `0`: presentation waits for the frame's own fence. `1` waits for the previous frame's fence, so the game prepares a frame while the emulated GPU finishes the last one; this is much faster, but OoT flickers again in Kokiri Forest when the camera turns. `-1` does not wait. The variable applies to all games. |
| `EDEN_N2DEN_PRESENT_GUEST_WAIT=1` | Experiment (off by default; from the Eglantine Community, 1cd9f57f3a). For the first 50 ms of the presentation's fence wait, the service thread sleeps in the guest kernel in 100 µs slices instead of blocking the host thread. This frees the guest core where am runs (+10 fps in OoT in Eglantine). Longer waits finish in the host wait. Off because in Mario Kart World it let the game overwrite command memory the GPU had not read yet (the game froze, then closed). |
| `EDEN_N2DEN_PENDING_SLEEP=1` | Restores the fixed 1 ms sleep of the GPU thread while a channel waits on a semaphore. By default the wait ends as soon as the next command arrives (from the Eglantine Community, 94424afdbd, pending_wake: +1.5 fps in OoT there). |
| `EDEN_GUEST_WAIT_STATS=1` | Every 4 s, logs what the game threads block on (events, addresses, mutexes, sleeps, IPC per service) and how long each HLE service command takes. Costs up to about 15% fps while on. |
| `EDEN_N2DEN_LUMA_TRACE=1` | Measures the average brightness of each presented frame (read a few frames later, without waiting) and logs every 4 s the isolated frames that differ from their neighbours. Finds one-frame flickers that screenshots miss. |
| `EDEN_N2DEN_UPLOAD_STATS=1` | Logs every 4 s how much CPU-written data the buffer cache uploads per frame: distinct 4 KiB pages, KiB, copies, and pages also uploaded in the previous frame. Sizes a capture of this data at the game's submit instead of at bind (`video_core/upload_stats.h`). |
| `EDEN_JIT_CACHE=0` | Turns off the on-disk cache of translated CPU blocks (on by default). Each game has a `<cache>/jit/<program id>.bin` file with the optimized Dynarmic IR of each block. A record is used only if the game's instructions in memory still match the ones that were translated, and a file from another build is discarded. With the cache on (and no RNG seed configured), each game's ASLR uses a fixed offset derived from the program id, because the blocks hold absolute addresses. |
| `EDEN_JIT_CACHE_DIR=<folder>` | Stores the on-disk CPU block cache in `<folder>/<program id>.bin` instead of `<cache>/jit/` (off by default). For cold- or warm-cache measurements without reading or rewriting the profile's file (a file from another build is rewritten). The NVN pipeline cache equivalent is `EDEN_NX2_NVN_CACHE_DIR`, which also holds the device's `vulkan_static_pipelines.bin`. |
| `EDEN_JIT_CACHE_STATS=1` | Every 30 s and when the game closes, logs per core how many blocks came from the cache and how many were translated, plus the time spent translating, reading the cache and emitting x64 code. |
| `EDEN_JIT_HOT_MAP=1` | Keeps, per core, a table of which range of Dynarmic x64 code belongs to which game block (start and end PC), filled when a block is emitted or loaded from the cache. The debug server's `jit_hot` call uses it to report which game blocks the JIT time is spent in. Costs about 24 bytes per block (about 50 MB in OoT). Off by default. |
| `EDEN_WINDOW_TITLE` | Window title in eden-cli (used internally by the frontend itself). |

The tests in `src/tests/video_core/native_shader.cpp` still read `EDEN_NATIVE_SHADER_FIXTURES`
and related variables (optional, only for running the tests with fixtures).
