# Cortex-A78C coverage and the block cache

The Switch 2 runs games on Cortex-A78C cores. For user-mode code that means ARMv8.2-A plus the extensions clang
enables for `-mcpu=cortex-a78c`: FP16, RDM, DotProd, LSE, LRCPC, FlagM, PAuth, CRC32/AES/SHA, DPB, SSBS and RAS.

## What the A64 frontend covers

All of the above, scalar and vector:

| Feature | Instructions |
| --- | --- |
| FEAT_FP16 | Half-precision arithmetic, min/max, sqrt, compares (incl. FCMP/FCCMP/FCSEL), pairwise, across-lanes, by-element, integer and fixed-point conversions (incl. SCVTF/UCVTF from general registers) |
| FEAT_RDM | SQRDMLAH, SQRDMLSH (vector, scalar, by element) |
| FEAT_LSE | CAS, CASP, SWP, LDADD/LDCLR/LDEOR/LDSET, LDSMAX/LDSMIN/LDUMAX/LDUMIN and the ST* aliases, all sizes and orderings |
| FEAT_LRCPC, FEAT_LOR | LDAPR(B/H), LDLAR, STLLR |
| FEAT_FlagM | CFINV, RMIF, SETF8, SETF16 |
| FEAT_PAuth | PAC*/AUT*/XPAC*, PACGA, RETAA/RETAB, BRAA/BRAB/BLRAA/BLRAB (+Z forms), LDRAA/LDRAB |
| ARMv8.0 gaps found in Switch 2 SDK code | SQRSHL, UQRSHL, scalar SQRSHRN/SQRSHRUN/UQRSHRN, SQDMLAL/SQDMLSL(2), scalar SQDMULL |

PAuth follows the existing model (`enable_pauth_returns`): keys disabled, so signing is a no-op, authentication
leaves pointers unchanged and XPAC strips the high bits.

Half-precision arithmetic is exact soft-float (`common/fp/op/FPHalfArith`), including NaN propagation,
FPCR.DN/FZ16/RMode and FPSR flags. The x64 backend calls it per lane; the arm64 and riscv64 backends stub these
opcodes like their other half-precision ones (A64 guests use NCE on ARM hosts).

Not included, because the A78C does not have them: FHM (FMLAL), FRINT32/64, JSCVT, FCMA half-precision (UNDEFINED),
MTE, BTI.

## Testing

`dynarmic_a64_probe` (tests/a64_probe.cpp) has modes for:

- `coverage`: which words translate and which raise UnallocatedEncoding. An audit script (not included in this
  repository) feeds it every value of bits [31:10] with fixed register fields, plus random words and the words of a game image,
  and compares with `llvm-objdump --mcpu=cortex-a78c`. Result: everything an A78C accepts in user mode translates,
  except non-canonical "should be one" field encodings, and nothing crashes the translator.
- `run`: execute a case and print the final state, for differential tests against unicorn's `max` CPU (QEMU).
  ~40,800 cases over every new instruction match, except where QEMU itself is wrong (signed LSE min/max compared
  unsigned; FP16 fixed-point scalar results sign-extended to 32 bits).
- `runcache` / `bench`: the block cache below.

`tests/A64/armv82.cpp` checks the new instructions against values worked out from the Arm ARM pseudocode.

## Block cache

`UserConfig::block_cache` (interface/A64/block_cache.h) lets the embedder keep translated blocks across runs. On a
miss the JIT translates and optimizes as usual and stores the optimized IR (ir/block_serialization) with a hash of
the guest instructions. On a later run the record is used only if the guest code still hashes the same; the key
includes a fingerprint of the IR schema and the JIT configuration. Instruction names are kept, so fastmem
fallbacks keyed by them still apply to cached blocks.

With `UserConfig::block_cache_native`, records also hold the block's x64 code in relocatable form
(backend/x64/native_cache.h). While recording, the emitter keeps constants in the block, uses fixed-length calls
and rel32 branches, and records every embedded host address: functions and statics of the module (relative to its
base), prelude routines (relative to the code space), and JIT objects (callbacks, configuration, TPIDR, exclusive
monitor slots) as symbols resolved for the core that loads the block; the other cores' monitor slots are symbols
relative to the loading core, so one copy of the code serves every core. Links to other blocks are rewritten on
load and fastmem entries are re-registered. An immediate that points into mapped host memory without being
recorded makes the block non-relocatable (it is then cached as IR only). `block_cache_verify_native`
(`EDEN_JIT_CACHE_VERIFY=1`) compares relocated cached code with freshly generated code byte for byte.

n2den stores the records per program in `<cache dir>/jit/<program id>.bin` (core/arm/dynarmic/jit_block_cache):
zstd-compressed, memory-mapped, with only an index in memory. Emulation > Configure > CPU > JIT disk cache selects
Off, Translations, or Translations + x64 code. `EDEN_JIT_CACHE=0` forces it off; `EDEN_JIT_CACHE_STATS=1` logs
per-core counters every 30 s and on shutdown.

Cached blocks hold absolute guest addresses, so they only apply when a program loads at the same base. The loader
otherwise picks a random ASLR page offset on every boot; with the cache enabled (and no RNG seed configured) it
uses an offset derived from the program id instead: stable across boots of a game, different between games.

Ocarina of Time (Switch 2), the same scripted 190 s boot to the title screen in each mode, 6 emulated cores, JIT
CPU time summed over cores (cache already filled for the cached modes):

| JIT disk cache | blocks translated | translate | cache load | x64 emit | total |
| --- | --- | --- | --- | --- | --- |
| Off | 763,424 | 1.58 s | - | 4.49 s | 6.07 s |
| Translations | 135 | 0.01 s | 1.19 s | 4.58 s | 5.77 s |
| Translations + x64 code | 135 | 0.01 s | 1.42 s | 0.03 s | 1.46 s |

Loading a block with x64 code takes ~1.8 us: storage (LZ4) ~0.55 us, parsing ~0.33 us, guest code hash ~0.08 us,
placement ~0.9 us. Time to the first frame and to 3,000 frames was the same in all three modes: the JIT runs on
six cores and does not bound this boot. The cache file is ~171 MB with x64 code.

Verification over 20,000 OoT functions,
loaded in a second process, found the cached code identical to fresh code in every block.
